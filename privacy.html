Spottr

Your evidence stays local.

Effective October 22, 2026. This notice covers Spottr’s downloadable Chrome extension.

What Spottr handles

When you save a note, Spottr stores the text you enter; the selected screenshot crop, if any; the page URL and title when Chrome provides them or you enter them; available viewport and scroll details; selection coordinates; project and QA session names and identifiers; and timestamps. The URL is also normalized with common temporary token parameters removed.

Where data is stored

Notes and screenshots are stored in IndexedDB inside Spottr’s Chrome extension storage. Project, session, and active-workspace state are stored in chrome.storage.local. The data is local to the Chrome profile where Spottr is installed. Spottr does not use storage.sync. For Capture area on restricted pages, a full visible-tab screenshot is held as a temporary local draft while you choose an area. Add text-only note takes no screenshot. Saving or discarding removes the draft; a new capture replaces an unfinished one. Closing the editor alone leaves the draft until the next capture or extension-data removal.

What leaves the browser

Spottr has no developer-operated server, account system, cloud sync, analytics, advertising, or telemetry. It does not automatically transmit saved evidence. Data leaves Spottr only when you intentionally copy an export to the clipboard, download an export file, or share either result using another tool.

Retention and deletion

Spottr does not automatically expire saved data. A note remains until you delete it, clear its QA session or project, remove Spottr’s extension data in Chrome, or uninstall the extension. Deleting a note also deletes its locally stored screenshot. Clearing notes keeps the empty project and session until you explicitly delete those containers.

Access and permissions

Spottr receives temporary access to the active tab only after you click a capture action or use a configured shortcut. On regular webpages, it displays an in-page capture interface. On restricted pages, it opens Spottr’s own editor without reading the page DOM. It uses Chrome’s screenshot API only when you choose Capture area. Chrome may withhold the source URL and title. Spottr does not request persistent access to every website.

Your responsibility when sharing

Screenshots, URLs, page titles, and written notes can contain confidential or personal information. Review and redact exported evidence before sharing it. Spottr does not automatically detect secrets or sensitive content.

Use of captured data

Spottr’s handling of user data is limited to providing its single purpose: user-initiated capture, organization, local review, and export of frontend QA evidence. Spottr does not sell user data, use it for advertising or creditworthiness, transfer it to third parties, or permit human access by the developer.

Changes and questions

If Spottr’s data handling changes, this notice must be updated before that change is published. For help, visit the Spottr issue tracker or review the local troubleshooting guide.
